# Virtual Studio

## Purpose

The studio is a social and contextual navigation layer.

It should increase:
- presence
- communication
- team awareness
- project identity

It should not reduce productivity.

## Initial Rooms

Keep V1 small.

Recommended:

### Lobby
General entry point.

### Programming Room
Programmer presence and programming-related progress context.

### Art Room
Art team presence, references, embeds, and progress.

### Design Room
Game design context and planning references.

### Meeting Room
Shared discussion context.

Rooms can later become configurable.

## Avatar

V1 avatar requirements:

- top-down 2D
- idle animation
- walk animation
- direction
- collision
- display name
- online presence
- basic profile interaction

Do not spend excessive V1 effort on:
- deep character customization
- cosmetics
- complex emotes
- physics
- combat/gameplay

## Avatar Interaction

Suggested actions when selecting a member:

- View Profile
- Chat
- View Current Goal
- View Progress

## Objects

Every interactable object should have a real function.

Examples:

### Desk
Shows member/current work context.

### Monitor
Opens external resource, embed, or work preview.

### Project Board
Opens project progress.

### Meeting Table
Opens meeting/group context.

## Efficiency

Do not force users to walk to perform essential tasks.

Support direct navigation through:
- sidebar
- search
- command palette later
- board view

Studio interaction is an enhancement, not a gate.
